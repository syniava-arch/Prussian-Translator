# Переводчик · Prūsiska bilā (черновик)

Экспериментальный пословный переводчик русский → прусский, построенный
поверх данных словаря **Prūsiska bilā**. Отдельный репозиторий — от
основного сайта словаря не зависит и никак на него не влияет; это
самостоятельная площадка для долгой обкатки идеи.

**Живая страница (после деплоя):** `https://<ваш-логин>.github.io/<имя-репозитория>/`

## Как это устроено

Морфологический разбор русского языка (лемма, падеж, число, время,
лицо) выполняет `pymorphy3` — библиотека на Python. Чтобы обойтись без
сервера и разместить всё на GitHub Pages как статический сайт, Python
запускается прямо в браузере через **Pyodide** (Python, скомпилированный
в WebAssembly). Логика перевода — в `translate_core.py`, `app.js` только
загружает Pyodide, ставит `pymorphy3` и `pymorphy3-dicts-ru` через
`micropip`, подгружает JSON словаря и вызывает python-функции.

Схема разбора фразы:
1. `pymorphy3` определяет лемму, часть речи и грамматические признаки
   каждого русского слова.
2. Лемма ищется среди русских переводов в `dictionary.json`.
3. Если для найденного слова в `overrides.json` есть парадигма
   склонения/спряжения — берётся нужная форма (падеж/число или
   время/лицо/число).
4. Предлоги ищутся отдельно и передают управляемый падеж следующему
   слову (данные о падежном управлении уже размечены в поле `s`
   прусских предлогов).
5. При нескольких прусских переводах одного русского слова выбирается
   вариант, чья часть речи совпадает с частью речи русского слова.

## Структура репозитория

```
index.html          страница
style.css            оформление (палитра как у основного сайта словаря)
app.js               загрузка Pyodide/pymorphy3, обвязка интерфейса
translate_core.py    вся переводческая логика (без изменений для теста вне браузера)
data/
  dictionary.json    копия data/dictionary.json основного репозитория
  overrides.json     копия data/overrides.json основного репозитория
```

## Деплой на GitHub Pages

1. Создайте новый **пустой** репозиторий на GitHub (без README/лицензии).
2. Загрузите в него все файлы из этой папки, сохранив структуру
   (включая подпапку `data/`).
3. Settings → Pages → Source: **Deploy from a branch**, ветка `main` /
   `master`, папка `/ (root)`. Сохраните.
4. Через минуту-две сайт появится по адресу вида
   `https://<логин>.github.io/<репозиторий>/`.

Оба JSON-файла в `data/` — обычные файлы, GitHub Pages отдаёт их без
проблем (как и на основном сайте, единой проблемы с лимитом размера
файла тут нет).

## Обратная связь от тестировщиков

На странице есть кнопка «Сообщить об ошибке / оставить комментарий» под
каждым переводом (с автоматически собранным отчётом: фраза, перевод,
разбор по словам) и отдельная общая форма отзывов внизу страницы.
Работает в трёх вариантах одновременно:

- **Скопировать отчёт** — работает всегда, без всякой настройки; текст
  можно вставить куда угодно (Telegram, форум, письмо вручную).
- **Открыть issue на GitHub** — появляется, только если в `app.js`
  заполнено поле `FEEDBACK_CONFIG.githubRepo` (например
  `"stanislavas/prussian-translator"`). Узнать это можно только после
  того, как вы создадите репозиторий — впишите его туда и закоммитьте
  ещё раз. Issues должны быть включены в репозитории (Settings → General
  → Features → Issues; на публичных репозиториях включены по умолчанию).
- **Написать на почту** — появляется, только если заполнено
  `FEEDBACK_CONFIG.email`. Открывает `mailto:` со собранным текстом.

Обе настройки — в самом начале `app.js`:

```js
const FEEDBACK_CONFIG = {
  githubRepo: "",  // "ваш-логин/имя-репозитория"
  email: "",       // "you@example.com"
};
```

Если оставить оба поля пустыми, тестировщики всё равно смогут
скопировать отчёт и прислать его вам любым удобным способом — сайт
ничего не отправляет за них сам и никуда не пишет напрямую (это
статическая страница без сервера).

## Обновление словарных данных

`data/dictionary.json` и `data/overrides.json` здесь — **копия на
момент подготовки**, не связаны live с основным репозиторием. Когда в
основном словаре появятся новые слова или уточнённые парадигмы, эти
два файла нужно вручную скопировать заново из `data/` основного
репозитория и закоммитить сюда.

## Известные ограничения (честно)

- **Падежная неоднозначность без контекста.** У неодушевлённых
  существительных м.р. именительный и винительный падеж по-русски
  совпадают по форме — без предложного управления скрипт иногда берёт
  не тот падеж (например, прямое дополнение без предлога: «вижу дом»
  может выйти в именительном вместо винительного).
- **Не все предлоги и служебные слова есть в словаре** — некоторые
  русские слова («домой» и т.п.) вернутся как «нет в словаре».
- **Порядок слов** просто копируется с русского — правил прусского
  синтаксиса (порядок слов, согласование прилагательных) нет.
- **Омонимия внутри одной части речи** не разрешается — берётся первое
  совпадение.
- Перевод возможен только там, где для слова есть готовая парадигма в
  `overrides.json`; для остальных слов подставляется словарная форма
  без склонения (это видно в разборе по словам).
- **Первая загрузка страницы** тянет Pyodide (~10 МБ) и словарь форм
  pymorphy3 (~8 МБ) из CDN (`cdn.jsdelivr.net`) и PyPI — нужен интернет
  и это может занять 10-20 секунд. Дальше браузер кэширует файлы, и
  повторные заходы будут быстрее (если не делать hard refresh).

## Локальная проверка перед деплоем

`translate_core.py` — обычный Python-модуль, его можно погонять и без
браузера:

```bash
pip install pymorphy3 pymorphy3-dicts-ru
python3 -c "
import translate_core as tc
tc.load_data(open('data/dictionary.json', encoding='utf-8').read(),
              open('data/overrides.json', encoding='utf-8').read())
print(tc.translate_sentence_json('Брат идёт в лес'))
"
```

## Дальнейшие шаги

- Обработка локатива/инструменталиса, если такие данные появятся в overrides.
- Разрешение омонимии по семантике/частотности, а не только по части речи.
- Базовые правила порядка слов и согласования.
- Возможный перенос лучших наработок обратно на основной сайт словаря —
  после того как логика будет обкатана и одобрена.
