# Переводчик · Prūsiska bilā (черновик)

Экспериментальный rule-based переводчик русский ↔ прусский поверх данных
словаря **Prūsiska bilā**. Это не нейросетевой переводчик и не готовая
литературная система: цель проекта — постепенно улучшать словарный перевод,
морфологию, устойчивые выражения и разбор простых конструкций.

**Живая страница после деплоя GitHub Pages:**
`https://<ваш-логин>.github.io/<имя-репозитория>/`

## Как это устроено

Морфологический разбор русского языка выполняет `pymorphy3`. Чтобы сайт можно
было разместить как статический GitHub Pages, Python запускается прямо в
браузере через **Pyodide**. Основная логика перевода находится в
`translate_core.py`, а `app.js` загружает Pyodide, устанавливает `pymorphy3`,
подгружает данные и вызывает Python-функции.

Сейчас переводчик делает не только строго пословный поиск, но и несколько
простых rule-based шагов:

1. ищет многословные словарные статьи и выражения из `data/phrasebook.json`;
2. разбирает русские формы через `pymorphy3`;
3. выбирает словарную статью по части речи и наличию парадигмы;
4. склоняет/спрягает прусские формы по данным `overrides`;
5. различает некоторые предложные конструкции, например `в дом` vs `в доме`;
6. согласует прилагательные/местоимения с ближайшим существительным;
7. применяет простую эвристику прямого дополнения после переходных глаголов;
8. умеет обратный поиск PR → RU по словарным формам и формам из парадигм.

## Данные и shard-файлы

Исходные копии словаря остаются в `data/`:

```text
data/dictionary.json
data/overrides.json
```

Для размещения на GitHub Pages также подготовлены маленькие индексные части:

```text
data/shards/manifest.json
data/shards/dictionary/000.json ...
data/shards/overrides/000.json ...
```

`app.js` сначала пробует загрузить `data/shards/manifest.json` и shard-файлы.
Если их нет, автоматически откатывается к старому режиму с большими
`dictionary.json` и `overrides.json`.

Пересобрать shard-файлы можно командой:

```bash
python3 scripts/build_data_shards.py
```

Скрипт читает `data/dictionary.json` и `data/overrides.json`, режет их на
маленькие JSON-массивы примерно до 600 KiB каждый и обновляет manifest. Эти
файлы уже закоммичены, поэтому отдельный build step для GitHub Pages не нужен.

## Структура репозитория

```text
index.html                    страница
style.css                     оформление
app.js                        загрузка Pyodide/pymorphy3 и данных
translate_core.py             основная логика перевода
.nojekyll                     отключает обработку Jekyll на GitHub Pages
scripts/build_data_shards.py  генератор маленьких shard-файлов

data/
  dictionary.json             исходная копия словаря
  overrides.json              исходные парадигмы/спряжения
  phrasebook.json             ручные устойчивые выражения и алиасы
  shards/                     маленькие индексные JSON для статического хостинга
```

## Деплой на GitHub Pages

### Вариант A — через настройки Pages

1. Загрузите/запушьте все файлы репозитория на GitHub.
2. Откройте **Settings → Pages**.
3. Source: **Deploy from a branch**.
4. Branch: `main` или нужная рабочая ветка.
5. Folder: `/ (root)`.
6. Сохраните. Через минуту-две сайт будет доступен по адресу вида
   `https://<логин>.github.io/<репозиторий>/`.

### Вариант B — если используете отдельную ветку

Можно включить Pages для ветки с подготовленными файлами. Важно, чтобы в корне
ветки лежали:

```text
index.html
app.js
style.css
translate_core.py
data/
.nojekyll
```

Никакой сервер не требуется.

## Обратная связь от тестировщиков

На странице есть кнопка «Сообщить об ошибке / оставить комментарий» под
каждым переводом (с автоматически собранным отчётом: фраза, перевод,
разбор по словам) и отдельная общая форма отзывов внизу страницы.
Работает в трёх вариантах одновременно:

- **Скопировать отчёт** — работает всегда, без всякой настройки; текст
  можно вставить куда угодно (Telegram, форум, письмо вручную).
- **Открыть issue на GitHub** — появляется, только если в `app.js`
  заполнено поле `FEEDBACK_CONFIG.githubRepo` (например
  `"stanislavas/prussian-translator"`). Узнать это можно только после
  того, как вы создадите репозиторий — впишите его туда и закоммитьте
  ещё раз. Issues должны быть включены в репозитории (Settings → General
  → Features → Issues; на публичных репозиториях включены по умолчанию).
- **Написать на почту** — появляется, только если заполнено
  `FEEDBACK_CONFIG.email`. Открывает `mailto:` со собранным текстом.

Обе настройки — в самом начале `app.js`:

```js
const FEEDBACK_CONFIG = {
  githubRepo: "",  // "ваш-логин/имя-репозитория"
  email: "",       // "you@example.com"
};
```

Если оставить оба поля пустыми, тестировщики всё равно смогут
скопировать отчёт и прислать его вам любым удобным способом — сайт
ничего не отправляет за них сам и никуда не пишет напрямую (это
статическая страница без сервера).

## Обновление словарных данных

Когда обновляются исходные словари:

1. замените `data/dictionary.json` и/или `data/overrides.json`;
2. выполните:

   ```bash
   python3 scripts/build_data_shards.py
   ```

3. проверьте перевод локально;
4. закоммитьте изменённые исходные JSON и `data/shards/`.

## Локальная проверка без браузера

`translate_core.py` можно прогнать как обычный Python-модуль:

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install pymorphy3 pymorphy3-dicts-ru
python3 - <<'PY'
import translate_core as tc
stats = tc.load_data(
    open('data/dictionary.json', encoding='utf-8').read(),
    open('data/overrides.json', encoding='utf-8').read(),
    open('data/phrasebook.json', encoding='utf-8').read(),
)
print(stats)
print(tc.translate_sentence_json('Я вижу молодого человека'))
print(tc.translate_pr_sentence_json('aulaūwuns'))
PY
```

## Известные ограничения

- Перевод всё ещё rule-based и частично пословный: сложный синтаксис,
  придаточные предложения и свободный порядок слов пока не анализируются.
- Эвристика прямого дополнения помогает с фразами вроде `вижу дом`, но не
  заменяет полноценный синтаксический parser.
- При нескольких значениях одного русского слова переводчик всё ещё может
  выбрать не тот смысл.
- Устойчивые выражения требуют ручного пополнения `data/phrasebook.json`.
- Первая загрузка тянет Pyodide и `pymorphy3` из CDN/PyPI, поэтому может
  занимать 10–20 секунд; дальше браузер обычно кэширует зависимости.

## Дальнейшие шаги без backend

- Расширять `data/phrasebook.json` устойчивыми выражениями.
- Добавить маленький `verb_frames.json` для управления глаголов.
- Добавить тестовый корпус примеров RU↔PR.
- Постепенно выделять перевод именных/предложных групп в отдельные функции.

Для качественного литературного перевода в будущем всё равно понадобится более
серьёзный синтаксический слой или backend, но текущая структура уже пригодна
для статического GitHub Pages.
